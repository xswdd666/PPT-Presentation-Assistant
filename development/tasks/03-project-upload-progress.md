## 路由责任

- `/projects`：项目列表与最近状态。
- `/projects/new`：新建项目。
- `/projects/:projectId/upload`：上传、目标信息、分析进度、失败与重新分析。
- 分析成功后跳转 `/projects/:projectId/review`；不要在本任务实现该页面内容。

若现有路由框架不同，可保持等价语义，并在交接中给出最终映射。

## 实施顺序与完成标准

### 1. 项目与上传数据模型

- 建立项目、源文件、派生版本和分析 Job 的真实持久化。
- 每个项目保留不可变原始文件引用；后续版本不能覆盖源文件。
- 文件校验包含扩展名、MIME、大小、损坏文件和 60 页上限。
- 上传与任务创建支持幂等键，刷新页面不会重复生成项目或 Job。

完成标准：合法 PPTX 生成项目和唯一分析任务，非法文件得到可读错误。

### 2. 可选目标输入

- “汇报目标”和“期望听众回应”都不是必填项。
- 用户留空时显示 AI 建议生成状态与建议文本；用户可直接修改、接受或覆盖。
- 数据层区分 AI 建议值、用户确认值和最后修改时间。
- 用户在分析开始前修改目标时，以最新确认内容作为 DeckContext。

完成标准：两个字段全空也能提交；用户编辑后的值在刷新后保留。

### 3. 后台任务与进度

- Web 请求只创建任务，不在请求生命周期内完成整份 PPT 分析。
- 状态至少覆盖：等待上传、上传中、解析中、渲染中、AI 分析中、生成评审、完成、失败、取消。
- 进度由持久化状态读取，可采用轮询或项目现有机制；刷新或重连后继续显示真实状态。
- 每个失败状态包含错误码、可读说明、是否可重试和安全的重试入口。

完成标准：模拟慢任务和失败时，UI 不假完成，且可从持久化状态恢复。

### 4. 上传页面状态

- 实现空状态、拖放或选择文件、上传进度、分析进度、失败、重试和完成跳转。
- 视觉使用低饱和暖灰或冷灰、石墨蓝和克制钢蓝，不添加全局顶部导航。
- 页面应适配桌面端和窄屏；窄屏不要求同时展示工作台三栏。
- 无可用项目时给出明确下一步，不使用空白占位。

完成标准：键盘可完成文件选择与提交，进度有文本而不只依赖颜色。

## 测试要求

- API 或服务测试：合法上传、错误扩展名、损坏文件、超过 60 页、重复提交、Job 重试。
- 持久化测试：刷新恢复、源文件不可变、目标建议与用户确认值区分。
- UI 测试：空、上传中、分析中、失败、完成状态。
- 记录测试命令、结果和环境依赖。

## 任务边界

本任务提供项目入口与上传阶段，不实现评论筛选、评论详情、评论回复、文字 Diff、讲稿格式工具或版本导出。需要共享外壳时使用对话 04 暴露的接口，不复制一份导航组件。
